Architecture

How a question flows through the system

Campus Copilot is a multi-agent LangGraph workflow. A classifier routes each message to one of five specialist agents. Each specialist can call only the tools of its own domain (some local, some served over MCP) before it writes the answer. Every step is checkpointed in SQLite and streamed to this page.

1 · System architecture

Everything runs on one machine. The browser talks to FastAPI, which runs the LangGraph graph. The graph talks to the local LLM, to the tools and to the checkpointer.

2 · The agent graph (LangGraph StateGraph)

Nodes are Python functions and edges are transitions. Dashed arrows are conditional edges, decided at run time from the shared state.

3 · Life of one request

Example: “What is 125 × 38 + 17?”, from the click on Send to the streamed answer.

Workflow, step by step

1 · Receive

POST /api/chat with the message and a thread_id. FastAPI opens a Server-Sent-Events stream and calls graph.astream(..., stream_mode=["messages","updates"]).

2 · Restore memory

The AsyncSqliteSaver loads the last checkpoint of the thread. The new message is appended to state.messages by the add_messages reducer.

3 · Classify

The classifier calls the LLM with a JSON schema (Pydantic Route: enum category + confidence + reason), few-shot examples and the last turns, so that follow-up questions are routed correctly. An empty input goes to fallback without calling the LLM.

4 · Specialise

A conditional edge selects one of the five agents. Each one has its own system prompt and is bound only to its domain's tools (least privilege). trim_messages keeps the context window small.

5 · Act

If the model emits tool_calls, the shared ToolNode runs them: local Python tools, or MCP tools through the campus MCP server. Errors become ToolMessages instead of crashes.

6 · Loop back

route_after_tools reads state.category and goes back to the same agent, which reads the tool result and either calls another tool or writes the final answer.

7 · Stream

Tokens, node updates, routing and tool events are pushed to the browser as they happen. Here you see the answer being written and the trace filling up in the inspector.

8 · Persist & recover

A checkpoint is written after every super-step (time-travel history). LLM nodes have a RetryPolicy (3 attempts, exponential back-off), and the server turns a final failure into a friendly message.

HTTP API

EndpointDescription
POST /api/chatBody {message, thread_id}. Returns a stream of SSE events: route, node, tool_call, tool_result, token, error, done.
GET /api/threads/{id}Messages of a thread from the checkpointer, plus the number of stored checkpoints (time-travel history).
DELETE /api/threads/{id}Deletes all checkpoints of a thread.
GET /api/infoModel, MCP status, nodes and tools (with the agents allowed to use them).
GET /api/eval · POST /api/eval/runLast evaluation report / run the evaluation suite again.

pip install -r requirements.txt

python -m app.evaluate                      # evaluation report → data/eval.json
pytest -q                                   # unit + API tests
